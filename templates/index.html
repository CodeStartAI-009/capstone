How it works

  1. ValidateThe URL is checked and normalised on the server. Only public http(s) URLs are accepted.
  2. Extract17 lexical features of the registrable domain (for example google.com for admob.google.com) are computed automatically, in the exact order the model was trained on.
  3. PredictThe trained model (loading…) estimates the probability that the URL is phishing.
  4. ClassifyBelow the decision threshold is a low-risk prediction; above it is a phishing-risk prediction (moderate or high).
  5. Explain and recordUnusual feature values and URL observations are listed as evidence, and the scan is saved to the local history.

What you get

  • Web scanner with feature-level evidence
  • Scan history dashboard with statistics
  • Chrome extension that checks the current tab on request
  • REST API documented in docs/api.md

Technology

  • Python, Flask, SQLite
  • scikit-learn gradient boosting
  • PhiUSIIL Phishing URL Dataset
  • Chrome Manifest V3 extension

Security & privacy

  • The server never fetches the scanned URL
  • Server-side input validation, size and rate limits
  • Tokens in query strings are redacted before a scan is saved
  • No IP addresses or user agents are stored

Limitations

This result is an automated machine-learning risk assessment and is not a guarantee that a website is safe. On a held-out test set the model detected … of phishing URLs and wrongly flagged … of legitimate ones. It judges the registrable domain only, so phishing in subdomains of an attacker's domain and phishing pages on ordinary-looking or compromised domains are often missed.
