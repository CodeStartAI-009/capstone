# Chrome extension (Manifest V3)

The extension does two things:

1. **Automatic checks (new in extension 2.0.0).** A background service worker checks the address of every
   http(s) page you open. It shows the result on the toolbar badge, and moves the tab to a warning page when
   the API returns a **High** risk level. The warning page has **Go Back to Safety** and **Continue Anyway**.
2. **Manual check (popup).** Clicking the toolbar icon scans the current tab's full URL, as before, and saves
   it to the scan history.

The extension contains **no model and no prediction logic**. Every result comes from the project's
`POST /api/predict`, the same endpoint and response contract the web app uses. The decision thresholds are
the model's own (in `models/model_metadata.json`) and are not changed by the extension.

```
tab navigation ──► background.js (service worker)
                     │  origin only, e.g. https://shop.example   (path, query, fragment are NOT sent)
                     ▼
                   POST {API_BASE}/api/predict {"url": origin + "/", "source": "extension", "record": false}
                     │  Flask ─► ml.predictor ─► model v2.0.0 ─► Safe/Suspicious/Phishing + Low/Medium/High
                     ▼
                   badge LOW / MED / HIGH  ("…" checking, "?" failed, N/A not checkable, OFF disabled)
                     │ High (and no Continue Anyway for this site in this tab)
                     ▼
                   tab ─► warning.html ─► Go Back to Safety ─► previous checked page, or safe.html
                                       └► Continue Anyway   ─► the original URL, allowed once in this tab
```

## Files

| File | Purpose |
|---|---|
| `extension/manifest.json` | MV3 manifest: permissions, service worker, popup, CSP |
| `extension/config.js` | **The only place the API location and scan settings are set**: `API_BASE`, `REQUEST_TIMEOUT_MS`, `AUTO_SCAN_DEFAULT`, `RECORD_AUTO_SCANS_DEFAULT`, `SCAN_CACHE_TTL_MS`, `BYPASS_TTL_MS` |
| `extension/scan-core.js` | Shared by popup and worker: `unsupportedReason(url)`, `callApi(url, record)` (timeout, error handling, response checks), `ScanError` |
| `extension/background.js` | Service worker: navigation events, per-origin cache, badge, warning redirect, Go Back / Continue handlers |
| `extension/warning.html` / `warning.js` / `warning.css` | The interstitial "Potential Phishing Risk" page |
| `extension/safe.html` | Local fallback page for Go Back to Safety when the tab has no earlier checked page |
| `extension/popup.html` / `popup.css` / `popup.js` | Popup: manual scan, automatic-check status of the tab, the two settings |
| `extension/icons/` | PNG icons, generated by `python scripts/make_icons.py` |

## Why only the origin is sent automatically

The deployed model (v2.0.0) scores the site's **registrable domain** (`"model_input_view": "registrable"`),
so `https://shop.example/account?token=…` and `https://shop.example/` get the same features and the same
score. The worker therefore sends only `scheme://host[:port]/`. Paths and query strings, which can contain
reset tokens, session ids or e-mail addresses, never leave the browser during automatic checks.
`tests/browser/test_extension_autoscan.py::test_low_risk_page_is_checked_automatically_sending_only_the_origin`
checks the exact request body.

What is lost: the explanation's `userinfo` observation (text before `@`) cannot appear for automatic checks,
because the origin has no userinfo. The score is unaffected, because userinfo is not a model input.

Automatic checks are **not** saved to the scan history by default (`record: false`). The popup setting
"Save automatic checks to the scan history" turns this on; the stored URL is then the origin only.

## Permissions

| Permission | Why |
|---|---|
| `tabs` | Read the URL of tabs when they navigate or are activated, to check them without a click. Chrome shows this as "Read your browsing history". No page content is accessible with it. |
| `storage` | `chrome.storage.local`: the two settings. `chrome.storage.session` (memory only, cleared when the browser closes): per-tab state and the result cache, so they survive service-worker restarts. |
| `host_permissions: ["http://127.0.0.1:5000/*"]` | Call the API. Only the API origin is listed. |

Not requested: `activeTab` (not needed with `tabs`), `history`, `scripting`, `webRequest`,
`declarativeNetRequest`, `webNavigation`, `cookies`, `<all_urls>`, content scripts, `web_accessible_resources`,
`externally_connectable`. `tests/test_client_code.py` enforces this list. The extension CSP is
`script-src 'self'; object-src 'none'; base-uri 'none'`.

The previous version (1.1.0) deliberately had **no** background worker: it used `activeTab` and sent a URL
only when the user clicked. Automatic warnings require the extension to see every navigation, so 2.0.0
reintroduces a worker with `tabs`. This is a real privacy trade-off, reduced by sending only origins, not
storing them by default, caching results and offering an off switch.

## Automatic checks in detail (`background.js`)

| Event | What happens |
|---|---|
| `tabs.onUpdated` with a new URL, or status `loading` (reload) | `handleNavigation(tab, url, "navigation")` |
| `tabs.onActivated` (tab switch) | Re-shows the stored badge for that tab; scans only if the tab was never checked or the last check failed. Never redirects on a tab switch. |
| `tabs.onReplaced` (prerendered tab swapped in) | Treated as a navigation of the new tab |
| `tabs.onRemoved` | The tab's state is deleted |
| `storage.onChanged` (`autoScan`) | Off: badge OFF on all tabs. On: the active tab is checked. |
| `runtime.onInstalled` / `onStartup` | Same as above |

**Skipped without any request:** `chrome://`, `chrome-extension://`, `file://`, `javascript:`, `data:`,
`about:`, `blob:`, `view-source:`, `ftp:`, empty URLs, and the API's own pages (`API_BASE` origin, badge N/A).
Hosts that the API refuses (localhost, private networks; `400 UNSUPPORTED_HOST`) are shown as **N/A, not
checked**.

**Duplicates and caching.** Results are cached per origin in `chrome.storage.session` for
`SCAN_CACHE_TTL_MS` (5 minutes, up to 200 origins). Concurrent checks of one origin share a single request.
So path changes, fragment changes, reloads and single-page-app `history.pushState` changes on one site make
**one** API call. Failures are **not** cached: the next navigation tries again.

**Stale responses.** Each navigation of a tab gets a token. When a response arrives, it is applied only if
(a) it belongs to the tab's latest navigation and (b) the tab is still on the scanned origin
(`tabs.get` → `pendingUrl || url`). Check (b) also works after a service-worker restart, when the in-memory
tokens are gone. A slow High response for a page the user already left therefore never redirects the tab.

**Badge states.**

| Badge | Meaning | Tooltip starts with |
|---|---|---|
| `…` | Checking | "Checking this site's address…" |
| `LOW` (green) | API risk level Low | "Low-risk prediction for this site. This is not a guarantee that it is safe." |
| `MED` (amber) | Medium: visible caution, no interstitial | "Caution: moderate phishing-risk prediction…" |
| `HIGH` (red) | High: warning page shown, or Continue Anyway chosen | "High phishing-risk prediction…" |
| `?` (grey) | Check failed (API down, timeout, error, invalid response) | "This site could NOT be checked: <reason>" |
| `N/A` | Not checkable (API's own pages, local/private hosts) | "This page is not checked: <reason>" |
| (none) | Browser pages, files, other schemes | "This page is not checked: <reason>" |
| `OFF` | Automatic checks are switched off | "Automatic checks are off…" |

A failed or unchecked page is **never** shown as low risk.

**Medium risk** uses the existing design's "Phishing-risk prediction (moderate)" wording: an amber badge and
the popup text, without an interstitial. Only High interrupts the user.

## Warning page, Go Back to Safety, Continue Anyway

The warning page (`warning.html`) asks the worker for **this tab's** warning (`warning:get`). It never reads
the URL from its own address or from a message, so no other page can make it show or open an arbitrary URL.
All values are written with `textContent`. It shows:
- the host and full URL;
- the API's verdict, risk level and model phishing score;
- the domain the model assessed, and the model version;
- the API's summary (which states the thresholds) and up to 6 explanation items tagged *model feature* or
  *observation*;
- the API's disclaimer, with the measured recall and false-positive rate;
- a fixed note that the warning may be wrong: legitimate sites can be flagged and phishing sites missed.

| Action | Implementation |
|---|---|
| **Go Back to Safety** (`warning:back`) | Navigates the tab to its `lastSafeUrl`, the latest page in this tab that was checked successfully and was not High and not on the flagged origin. If there is none (for example a link opened in a new tab), it opens the local `safe.html`. The target never comes from the API or from a message. If the worker cannot be reached, the page itself opens `safe.html`, so the user is never stuck. |
| **Continue Anyway** (`warning:proceed`) | Stores `bypass = {origin, expires}` for **this tab only**, then navigates to the URL stored with the warning. Reloads, path changes and SPA navigation on that origin are not interrupted again. The badge stays **HIGH** with "You chose Continue Anyway". |

When the bypass ends:
- the tab navigates to a different origin (including a redirect to another site);
- the next page load after `BYPASS_TTL_MS` (30 min);
- the tab is closed;
- the browser is closed (`storage.session`).

Another tab opening the same site is warned again. The bypass does **not**:
- change the score or the cache;
- write anything to the scan history;
- create a global allow-list;
- count as evidence that the site is legitimate.

**Redirect chains.** Chrome reports the URL the tab finally commits, so a server redirect from A to a
high-risk B warns about B. If an allowed site redirects to another high-risk site, that new destination is
warned about too (`test_server_redirect_to_a_high_risk_site_is_warned_about`, simulated
`redirect chains` test).

### What Manifest V3 can and cannot guarantee

- **The page is not blocked before it loads.** Chrome tells the worker about a navigation once it has
  started (`tabs.onUpdated`). The API call takes milliseconds on localhost, but the risky page can begin to
  load and run scripts before the tab is moved to `warning.html`. Blocking before any content loads would
  need the decision before the request is sent (for example `declarativeNetRequest` rules prepared in
  advance), which a per-URL ML call cannot provide. **This is a warning, not a guaranteed block.**
- **Browser Back after a warning.** The flagged page stays in the tab's history behind the warning page.
  Pressing the browser's Back button from the warning page returns there and is warned again, so use **Go
  Back to Safety** (or Continue Anyway). The user is never trapped: both buttons always work, also when
  automatic checks are switched off.
- **Service-worker lifetime.** Chrome stops idle workers. All state needed later (warning, bypass,
  last-safe URL, cache) is in `chrome.storage.session`, and all listeners are registered at top level, so a
  restarted worker continues correctly. This is tested with `ServiceWorker.stopAllWorkers` in real Chrome.

## Message passing

| Message | Sender | Reads/changes |
|---|---|---|
| `warning:get` | warning page (its own tab) | Reads the tab's warning |
| `warning:back` | warning page | Clears the warning; navigates the sender's tab |
| `warning:proceed` | warning page | Sets the bypass for the sender's tab; navigates it |
| `status:get` `{tabId}` | popup | Reads one tab's automatic-check status text |

The worker answers only messages whose `sender.id` is this extension and whose `sender.url` is one of its
own pages. There are no content scripts and no `externally_connectable`, so web pages and other extensions
cannot send them. The tab-changing messages act only on `sender.tab.id`.

## Installation (developer mode)

1. Start the API: `python app.py`. It must listen on `http://127.0.0.1:5000`, or change the configuration
   below.
2. Open `chrome://extensions` and switch on **Developer mode** (top right).
3. Click **Load unpacked** and select the project's `extension/` folder. After updating the code, click
   **Reload** on the extension's card.
4. Pin *Phishing URL Scanner* from the puzzle-piece menu. Open any web page: the badge shows the automatic
   result. Click the icon for the popup.

## API base URL configuration

| Environment | `extension/config.js` | `extension/manifest.json` |
|---|---|---|
| Development (default) | `const API_BASE = "http://127.0.0.1:5000";` | `"host_permissions": ["http://127.0.0.1:5000/*"]` |
| Production | `const API_BASE = "https://YOUR-PRODUCTION-API";` | `"host_permissions": ["https://YOUR-PRODUCTION-API/*"]` |

No production API exists yet, so none is configured. Both lines must name the same origin, and
`tests/test_client_code.py` checks that they agree.
- **macOS:** if port 5000 is taken by the AirPlay receiver (ControlCenter), start Flask with `API_PORT=5051`
  and use `http://127.0.0.1:5051` in both places, then click **Reload** on `chrome://extensions`.
- **Production:** also set the API's `CLIENT_ORIGIN` if a web frontend is hosted elsewhere. The extension
  itself doesn't need CORS, because `host_permissions` covers it.

## Popup behaviour

| Situation | Popup shows | Sent to API? |
|---|---|---|
| http(s) page | Verdict, prediction, risk level, model confidence, up to 4 reasons, disclaimer; **View details** (`/inspect?id=N`) and **Open dashboard**; the tab's automatic-check line; the two settings | yes: full URL, `record: true`, `source: extension` |
| `chrome://`, `about:`, `data:` pages | "Only http:// and https:// web pages can be scanned. This tab shows Chrome's internal pages / about: pages / data: URLs." | no |
| `file://` page | "…This tab shows local files." | no |
| The warning page | "…This tab shows extension pages." The automatic-check line still describes the tab's result | no |
| Malformed host / internal host (`localhost`, private IP) | The API's validation message | yes (rejected with 400, not stored) |
| API not running | "Cannot reach the scanner API at … Start the Flask server (python app.py) and try again." | n/a |
| No answer within 8 s | "The scanner API did not respond within 8 seconds. Try again." | n/a |
| API error / invalid response | The API's message, or "unexpected response (HTTP n)" | n/a |

Settings (stored in `chrome.storage.local`):
- **Check pages automatically and warn before high-risk sites** (default on, `AUTO_SCAN_DEFAULT`);
- **Save automatic checks to the scan history** (default off, `RECORD_AUTO_SCANS_DEFAULT`).

## Privacy

- **Automatic checks:** only the origin of http(s) pages, only to `API_BASE`, and not stored by default.
- **Manual popup scans:** the full URL, stored with query values redacted (see `docs/database.md`).
- **Never read or sent:** page contents, form fields, passwords, cookies or the browsing history. The
  extension has no content scripts and no access to page content.
- **Stored locally:** the two settings (`storage.local`). Per-tab state, including the last checked URL of
  each tab, and the result cache are kept in memory-only `storage.session` and disappear when the browser
  closes.
